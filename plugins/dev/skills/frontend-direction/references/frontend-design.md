# Intentional frontend design

Use this reference when establishing a visual direction or correcting a generic result. Keep the information allocation from frontend-content and the user's brief authoritative.

- Ground palette, typography, composition and imagery in the actual subject, audience and use. Do not recycle the last project's aesthetic.
- Choose one memorable element only when the brief calls for it; keep the surrounding layout quiet. A practical operational tool can be deliberately familiar.
- Let type, spacing and alignment express hierarchy. Use one or two deliberate type families; keep reading measures comfortable.
- Give structural devices meaning: number a real sequence, label a real group, use boundaries for relationships rather than decoration.
- Avoid default all-caps eyebrows, repeated card grids, unnecessary badges, decorative gradients and animations on every section.
- Treat words as functional design material: concrete actions, consistent names, informative empty/error states, no filler subtitles.
- Use motion for feedback and continuity; respect reduced motion and platform behavior.
- Record palette roles, type scale, layout intent and rationale in the design document/spec before implementation.
- Review the composition against the actual brief and inspect the rendered result when possible. Remove elements that add attention without adding meaning.
