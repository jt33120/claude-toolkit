# Layout

Structuring space on a page or screen. These are structural concepts, not
prescriptions — spacing/sizing values always come from the project's design
system.

| Name | Also called | What it is | Use when | Avoid when | Variants/states | Web (HTML/ARIA, shadcn/Radix) | iOS (SwiftUI) | Android (Compose/Material) | Alternatives |
|---|---|---|---|---|---|---|---|---|---|
| Container | Content wrapper, max-width wrapper | Element constraining content to a max width and centering/padding it | Keeping line length/content readable on wide viewports | Full-bleed content (hero images, canvases) | Fixed vs. fluid max-width, responsive breakpoints | `<div>` with max-width/`margin:auto`; shadcn layout primitives | `.frame(maxWidth:)` | `Modifier.widthIn`/`Box` with max width | Full-bleed layout |
| Grid | Grid layout | Two-dimensional layout arranging items into rows and columns | Content with both horizontal and vertical alignment needs (galleries, dashboards) | Simple one-dimensional sequences (use a stack) | Fixed columns, responsive/auto-fit, gap control | CSS Grid; shadcn via Tailwind grid utilities | `LazyVGrid`/`LazyHGrid` | `LazyVerticalGrid`/`LazyHorizontalGrid` | Stack, masonry, list |
| Stack | Flexbox row/column | One-dimensional layout arranging items in a row or column with consistent spacing | Most simple linear arrangements (default building block) | 2D alignment needs (use a grid) | Horizontal (`HStack`/row) vs. vertical (`VStack`/column), with/without wrap | CSS Flexbox `<div>`; shadcn via Tailwind flex utilities | `HStack`/`VStack`/`ZStack` | `Row`/`Column`/`Box` | Grid |
| Split view | Resizable panels, panes | Two or more adjacent panels with a draggable divider to resize each | Desktop apps needing simultaneous side-by-side content (editor + preview) | Mobile/narrow viewports (stack instead) | Fixed vs. resizable, collapsible panels, nested splits | Custom (`resize: horizontal` CSS, or libs); shadcn `Resizable` (react-resizable-panels) | `NavigationSplitView`, `HSplitView` (macOS) | Custom (no native Compose split view) | Master-detail, tabs |
| Master-detail | List-detail layout | Layout pairing a list/selector pane with a detail pane showing the selected item | Browsing many items while viewing one in depth (email, settings) | Single-focus flows with no "list of items" concept | Two-pane (tablet/desktop) vs. push-navigation (mobile) | Custom two-column layout | `NavigationSplitView` | Custom two-pane `Row` (List + detail) | Split view, drill-down navigation |
| Bento grid | Bento layout, mosaic grid | Grid of asymmetric, differently-sized tiles/cards in one composition | Dashboard/landing sections featuring several unequal-priority items together | Uniform content needing equal visual weight (use a regular grid) | Fixed template vs. responsive reflow | CSS Grid with spanning cells | `LazyVGrid` with custom spans | `LazyVerticalGrid` with custom spans | Regular grid, card list |
| Masonry | Pinterest-style grid, waterfall grid | Grid where items of varying height pack into columns without fixed row alignment | Variable-height visual content (photos, pins) where gaps would look bad in a regular grid | Content with fairly uniform height (use a regular grid) | Column count responsive to width | CSS `columns`/`grid-template-rows: masonry` (emerging); JS libs | Custom (staggered `LazyVGrid` via 3rd-party) | `LazyVerticalStaggeredGrid` (Compose Foundation) | Regular grid |
| Sticky header | Pinned header, fixed header | Header/section title that stays visible while its content scrolls beneath it | Long lists/sections where the heading/context should stay visible | Short content where scrolling away isn't a problem | Section-sticky (re-pins per group) vs. page-sticky | `position: sticky` | `.safeAreaInset`, `List` section headers (pinned) | `LazyColumn` `stickyHeader` | Fixed top app bar, scroll-to-top button |
| Safe area | Safe area insets, notch/inset padding | Padding that keeps content clear of device notches, home indicators, and system bars | Any full-screen mobile layout | Web layouts (no physical device insets, except PWAs) | Top/bottom/leading/trailing insets | CSS `env(safe-area-inset-*)` | `.safeAreaInset`, automatic in `NavigationStack` | `WindowInsets`, `Scaffold` auto-handling | Fixed padding constants (fragile across devices) |
| Scroll area | Scroll container, custom scrollbar viewport | A viewport that scrolls its overflowing content, sometimes with custom-styled scrollbars | Content taller/wider than its container, especially where custom scrollbar styling is wanted | Content that always fits (avoid unnecessary scroll containers) | Vertical, horizontal, both; native vs. custom-styled scrollbar | `overflow: auto` `<div>`; shadcn `ScrollArea` (Radix) | `ScrollView` | `Modifier.verticalScroll`/`LazyColumn` | Pagination, "load more" |
| Divider | Separator, hairline | Thin line separating groups of content | Visually separating unrelated sections/list groups | Sections already separated by spacing/cards (redundant) | Horizontal vs. vertical, inset (indented) vs. full-bleed | `<hr>`; shadcn `Separator` (Radix) | `Divider` | `HorizontalDivider`/`VerticalDivider` (M3) | Whitespace/spacing alone, section header |
| Aspect ratio box | Aspect ratio container | Wrapper that maintains a fixed width:height ratio for its content (e.g. media) | Preventing layout shift for images/video/embeds before they load | Content with intrinsically variable/unknown proportions | Common ratios: 1:1, 4:3, 16:9, 21:9 | CSS `aspect-ratio`; shadcn `AspectRatio` (Radix) | `.aspectRatio()` | `Modifier.aspectRatio()` | Fixed-height container (less flexible) |
| Hero section | Hero banner, splash section | Large, prominent block at the top of a page combining headline, visual, and primary CTA | Landing/marketing pages needing an immediate high-impact intro | Utility/dense app screens (wastes space) | Full-bleed image/video background, split-content layout | Composed `<section>` | Composed `VStack`/`ZStack` | Composed `Column`/`Box` | Simple page header, no hero at all |
| Bottom action bar | Sticky footer, action bar | Bar pinned to the bottom holding one or two primary action buttons (not navigation destinations) | A screen with one or two clear primary actions that should stay reachable while scrolling (checkout, forms) | More than a couple of actions, or destinations (use bottom navigation) | Single button, button pair, with safe-area padding | Fixed/sticky `<footer>` | `.safeAreaInset(edge: .bottom)` | `Scaffold(bottomBar:)` | Bottom navigation (destinations), inline button at content end |
| App shell | Page scaffold, layout shell | The persistent outer frame (header, nav, content slot) that wraps every screen of an app | Establishing consistent structural chrome across all screens | A single standalone screen (a full shell is overkill) | Header+sidebar+content, header+bottom-nav+content | Composed layout root; shadcn dashboard/app-shell blocks | `NavigationSplitView`/`TabView` as app root | `Scaffold` (M3) | Per-screen custom layout (no shared shell) |
