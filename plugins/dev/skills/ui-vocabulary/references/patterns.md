# UX patterns

Higher-level flows and strategies, usually composed from the components in
the other reference files. These are approaches to weigh, not defaults.

| Name | Also called | What it is | Use when | Avoid when | Variants/states | Web (HTML/ARIA, shadcn/Radix) | iOS (SwiftUI) | Android (Compose/Material) | Alternatives |
|---|---|---|---|---|---|---|---|---|---|
| Onboarding | First-run experience, welcome flow | Guided introduction shown to new users before/around first real use | Product needs upfront context or setup to be usable | Product is self-explanatory (skip straight to the app) | Slideshow/carousel intro, interactive walkthrough, checklist, progressive (in-context) | Composed screens/`Carousel` | Composed `TabView(.page)` screens | Composed `HorizontalPager` screens | Empty-state CTAs, contextual tooltips (progressive onboarding) |
| Empty state (pattern) | Zero state design | The design strategy of using a no-content moment to guide the user's next action | Any list/section that can legitimately be empty | — | See `feedback.md` "Empty state" for the component itself | — | — | — | Onboarding checklist, sample/demo data |
| Wizard | Multi-step form, guided flow | A task split into sequential, often linear steps, each with its own screen | Complex forms/setups better chunked than shown all at once | Short forms (a single page/dialog is simpler) | Linear vs. jump-around, with progress stepper, save-and-resume | Composed multi-screen/multi-dialog + `Stepper` (nav) | Composed `NavigationStack` screens | Composed screens + `HorizontalPager` | Single long form with sections, accordion form |
| Progressive disclosure | Layered disclosure | Showing only essential options up front, revealing advanced ones on request | Interfaces with a simple common path and rarer advanced options | All options are equally likely to be needed (disclosure just adds a click) | "Advanced" toggle/section, "Show more", nested settings | Collapsible/accordion + "Show more" link | `DisclosureGroup` | `AnimatedVisibility` + "Show more" | Full exposure with grouping/sectioning instead |
| Inline edit | Edit-in-place, click-to-edit | Editing a value directly where it's displayed, without navigating to a separate form | Quick single-field edits (a title, a table cell) | Multi-field edits needing validation/review before commit (use a form/dialog) | Click-to-edit text, always-editable field, auto-save vs. explicit confirm | Contenteditable/`<input>` swap-in | `TextField` toggled in place of `Text` | `TextField` toggled in place of `Text` | Edit dialog, dedicated edit screen |
| Drag and drop | DnD, reordering | Directly moving an item by dragging it to reorder, re-categorize, or transfer it | Manual reordering/sorting/organizing (lists, kanban, file upload) | Touch-hostile precision tasks, or when a simpler control (up/down buttons) suffices | Reorder-in-list, drag-between-containers, file-drop | HTML5 Drag and Drop API / pointer-based libs | `.draggable`/`.dropDestination`, `onMove` (List) | `Modifier.pointerInput` drag detectors, `LazyColumn` reorder libs | Up/down move buttons, cut/paste-style move actions |
| Infinite scroll | Endless scroll, auto-load feed | Automatically loading more content as the user nears the end of a list | Social/content feeds with large or unbounded item counts | Users need to reference/return to a specific position (use pagination) | Auto-load on scroll vs. "load more" button, with end-of-list state | `IntersectionObserver`-triggered fetch | `.onAppear` on last row | `LazyColumn` scroll position + fetch trigger | Pagination, "load more" button |
| Optimistic UI | Optimistic update | Updating the UI immediately on user action, before the server confirms, then reconciling/rolling back on failure | Fast-feeling interactions on generally-reliable actions (like, send, toggle) | High-stakes actions where a false success is costly (payments) | With silent rollback vs. visible error-and-revert | Client-state libs (React Query, SWR optimistic updates) | Local `@State` update ahead of network call | Local `State`/`MutableState` update ahead of network call | Pessimistic UI (wait-then-update), loading state |
| Undo | Undo action, "undo" affordance | Offering a brief window to reverse an action instead of confirming it up front | Reversible, low-cost-to-reverse actions (delete, archive, send) | Genuinely irreversible/costly actions (use a confirmation dialog instead) | Snackbar-with-undo, dedicated undo history/stack, keyboard shortcut (⌘Z) | Snackbar action; `history`/state-stack in app logic | Snackbar-style overlay + state stack | `Snackbar` action (M3) + state stack | Confirmation dialog (ask before, not after) |
| Search / filter / sort | Faceted search, list controls | The combined pattern of narrowing and ordering a collection: search (query), filter (facets), sort (order) | Any browsable collection beyond a handful of items | Very small, fully-visible collections | Filter panel/sidebar vs. filter chips, sort dropdown, combined search bar with scopes | Search field + filter chips/panel + `<select>` for sort | `.searchable` + filter `Menu` + sort `Picker` | `SearchBar` + `FilterChip` row + sort `DropdownMenu` | Faceted sidebar, saved views/presets |
| Settings screen | Preferences, options screen | Dedicated screen/section organizing configurable app/account options | Grouping configuration separate from core app flows | A single setting relevant in-context (put a toggle right there instead) | Grouped/sectioned list, search-within-settings, nested sub-screens | Composed list/form page | `Form` (grouped list style) | Composed `LazyColumn` with section headers | In-context toggle, inline preference control |
| Auth flow | Sign-in/sign-up flow, login flow | The sequence of screens/steps to authenticate or register a user | Any app requiring identity | Truly anonymous/no-account products | Password, magic link, OAuth/social, passkey, OTP-based, multi-factor | Composed forms + OAuth redirects | Composed `Form` + `AuthenticationServices` (Sign in with Apple) | Composed screens + Credential Manager API | Passwordless (magic link/passkey) instead of password |
| Paywall | Upgrade prompt, subscription gate | Screen/overlay blocking or limiting access until the user subscribes/pays | Gating premium features/content behind payment | Core functionality that should stay free (erodes trust if overused) | Hard paywall (full block) vs. soft (preview + prompt), feature-comparison table | Composed page/modal + payment provider embed | Composed `View` + StoreKit paywall | Composed `Composable` + Play Billing UI | Free trial, usage-based soft limits, freemium tier |
| Notification center | Notification inbox, activity feed | Centralized in-app list of past notifications/alerts the user can review | Notifications need to be revisitable, not just glanced at once | All notifications are purely transient (toast alone is enough) | Grouped by type/date, read/unread state, mark-all-read | Composed dropdown/page list | Composed `List` (often in a sheet) | Composed `LazyColumn` (often in a bottom sheet) | Toast/snackbar only (no persistent log), badge count alone |
| Command palette (pattern) | Quick actions, ⌘K pattern | See `navigation.md` "Command palette" for the component; here as a workflow-acceleration pattern for power users | App has many actions/destinations power users want fast keyboard access to | — | — | — | — | — | Keyboard shortcut cheat sheet, search field |
| Review & confirm step | Summary/review screen | A final step in a multi-step flow showing all entered data for review before committing | Any consequential multi-step submission (checkout, application) | Single-step, low-stakes actions | Editable summary (jump back to a step), read-only summary | Composed page/dialog | Composed `View` (final wizard step) | Composed `Composable` (final wizard step) | Inline validation throughout (no separate review), confirmation dialog |
| Workspace switcher | Organization switcher, account switcher | Control (usually in a corner menu) to switch between multiple workspaces/orgs/accounts | Multi-tenant SaaS where a user belongs to more than one workspace | Single-tenant apps | Dropdown with search, avatar-grouped list, "create new" entry | Composed `DropdownMenu`/`Popover` | Composed `Menu` | Composed `DropdownMenu` | Settings page list of workspaces (no quick switch) |
| Bulk actions toolbar | Batch action bar, selection toolbar | A toolbar that appears when multiple items are selected, offering actions across the whole selection | Lists/tables/grids where users act on many items at once (archive, delete, tag) | Single-item-at-a-time interactions (put actions on the row instead) | Floating vs. replaces default toolbar, with selection count and "clear selection" | Composed toolbar tied to `aria-selected` rows | Composed toolbar tied to `List(selection:)` | Composed `TopAppBar` action mode tied to selection state | Per-row action menu, drag-select |
| Comparison table | Pricing table, feature matrix | Side-by-side table comparing options/plans/products across shared attributes | Helping users choose between a few structured alternatives (pricing tiers, product specs) | Options that don't share comparable attributes | Highlighted "recommended" column, checkmarks vs. text cells | `<table>` styled; shadcn `Table` | Composed `Grid`/`Table` | Composed `LazyVerticalGrid`/`Table`-like layout | Card grid (one card per option), plain table |
